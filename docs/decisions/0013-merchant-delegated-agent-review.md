# 0013 商家侧的 agent 代理审核（提议）

- 状态：提议
- 日期：2026-10-26

## 背景

接入真实商家后，商家也可能希望用 agent 代理资料审核/评审。本记录只界定产品边界，
不改变当前实现；P1 验收完成后再按 ROADMAP 决定是否进入实现。

## 三层范围

- **L1 评审辅助**：对缺引用、过期、越权、要点删改做自动预检，只给提示，不改变状态；默认可用。
- **L2 agent 代理审核**：agent 给出 `approved`/`needs_revision` 建议，商家一键确认；
  需 tenant 级开关，且最终动作仍由商家账号完成。
- **L3 agent 代批准并发布**：仅商家显式 opt-in；必须 `reviewer_kind=agent` 且保留 24 小时可撤回窗口；
  L3 不得作为默认行为。

## 硬约束

a. **数据出域**：按租户开关 `tenant.agent_review_enabled`（默认关）；`merchant_admin` 开启时记录
   who/when/policy_version。只发送待审文档片段与评审规则，不发送顾客对话正文；审计只存发送内容的 sha256。
b. **审计字段扩展**：`admin_permission_request` 增加 `reviewer_kind`、`agent_attestation_sha256`、
   `agent_model_id`，保证能追溯“这条政策由谁批准”。
c. **顾客侧不披露“AI 审核”**，但商家管理台必须显式标注；不得把 agent 建议伪装成人工结论。

## 与 0005 的关系

0005 管的是“回复能否复制”，本决策管的是“资料能否发布”。两者遵循同一原则：
agent 不得代替人做最终动作；代理只提供带证据的建议，责任主体仍是商家。

## 后果

- 当前不改 admin 审核/发布代码，不新增迁移。
- 进入实现前需要：租户开关、审计字段迁移、管理台标注与撤回窗口的独立评审。
