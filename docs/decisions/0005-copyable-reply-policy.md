# 0005 客服可复制回复的条件

日期：2026-10-16　状态：已采纳

## 背景

首版的入口是客服辅助模式：客服把顾客的问题贴进工作台，拿到建议回复，复制回电商平台发送。现有实现刻意禁止复制模型输出，`can_copy` 始终为 false，数据库的 CHECK 约束、Go 的结果组装和前端都这样写死了。这条规则不放开，客服辅助模式就做不成。

## 决定

一条建议回复同时满足以下条件，才允许一键复制：

1. 执行已成功结束，不是 mock 结果；
2. 回复行为是 ANSWER，不是追问 CLARIFY，也不是转人工 HANDOFF；
3. 至少有 1 条通过权限、发布状态、有效期和披露检查的引用；
4. 由 Go 判定并持久化，前端只负责显示。

不满足时，界面照常显示回答和引用，但复制按钮不可用，并写明原因（例如"没有资料依据"或"需要追问"）。

## 理由

- 回复最后由客服人工发出，客服是最后一道关。
- 规则只放开"有出处的正式回答"，仍然守住[约束 9](../architecture.md#必须保留的设计约束)：证据不足时不让模型硬答。

## 后果

- M6 需要一个新的 checksum 迁移来调整 `customer_reply` 上的约束，并修改 Go 的结果组装和前端。
- 这条规则只适用于员工工作台。顾客直接看到的回答仍按原流程，由 Go 发布。
