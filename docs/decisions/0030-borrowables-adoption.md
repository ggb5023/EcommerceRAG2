# 0030 商用客服平台的借鉴采纳结论

- 状态：已采纳
- 日期：2026-10-30
- 相关：`docs/research/platform-borrowables.md`（调研全文）、工作包 02/03/04

## 决定

对照 Sierra、Decagon、Intercom Fin、Salesforce Agentforce 四家平台，**只抄约束，不抄功能**。
采纳结论如下，报告全文不复制进本决策。

### 采纳并已排期

| 项 | 内容 | 工作包 |
| --- | --- | --- |
| B6 | 决策理由落库（`turn_decision`） | 02 |
| B1 | 结果度量：自动解决率（只统计次数与 token） | 03 |
| B3 | 内容缺口闭环（缺口 → 补文档 → 回归） | 04 |

### 采纳但降级

| 项 | 降级形态 | 理由 |
| --- | --- | --- |
| B4 声明式能力 | 先做 domain 内的规则表（B4-lite），不做注册表与可视化 | 单商家场景，规则表即可覆盖 |
| B8 质检 | 先做确定性实体检查（B8-lite），不引入第二个模型 | 零模型成本，且能覆盖主要盲区 |
| B7 信任层 | 先产出"到底发了什么给模型"的事实清单，再决定是否脱敏 | 现状口径未经核实，先测后改 |

### 暂缓

| 项 | 前置 |
| --- | --- |
| B5 动作执行 | 需独立 ADR：动作层补偿语义、可撤销范围、审计口径。首个动作只做「备注待跟进」 |

### 不采纳

- 多 Agent supervisor 作为默认形态（确定性检查优先）；
- 按结果计费的产品形态（0021：只统计 token，不统计货币）；
- 可视化 workflow builder（声明式规则表足够）；
- 全量对话存档用于训练。

## 排期依据

按 **成本 × 风险 × 依赖** 排序，优先选择"不改行为"的项：
B6（零风险）→ B1（纯读）→ B3（纯读）→ B4-lite（低风险）→ B8-lite（行为变更，需重跑评测）
→ B2 置信分级（行为变更，依赖 B6/B8）→ B7（先出事实清单）→ B5（需独立 ADR）。

## 后果

- 四项"不采纳"写在这里，避免以后重复讨论。
