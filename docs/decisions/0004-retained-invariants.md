# 0004 重构中必须保留的设计约束

日期：2026-10-15　状态：已采纳

## 背景

重构会合并进程、前端和部署。现有实现中有一批数据和安全规则，已经被测试和故障演练证明有效，需要明确列出，防止重构时丢失。

## 决定

[架构文档](../architecture.md#必须保留的设计约束)列出的 11 条约束在重构中保持不变。它们的理由：

| 约束 | 防止的问题 |
| --- | --- |
| Go 唯一对外入口；权限只由 Go 决定 | 绕过授权直接调用 AI 或数据库 |
| 表级单写者加受限角色 | 两个服务写同一张表导致状态不一致 |
| checksum 迁移、应用不执行 DDL | 商家升级时 schema 被悄悄修改，无法审计 |
| 幂等键绑定请求摘要 | 网络重试导致重复回复、重复扣费 |
| 租约加 fencing epoch | worker 崩溃接管后，旧 worker 迟到写入覆盖新结果 |
| 引用绑定 document/version/chunk，撤回立即失效 | 回答引用已下架的政策，引发售后纠纷 |
| AI 只给建议，Go 发布 | 模型原始输出未经校验直接给到顾客 |
| 失败关闭、追问一次后转人工 | 证据不足时模型编造承诺 |
| 会话状态与 epoch | 人工接管后迟到的 AI 回答插进对话；两名客服同时回复 |
| 预算账本 | 开发和评测中模型费用失控 |
| 冻结评测集 | 为了让新功能"通过"而改真值，质量回退无法发现 |

## 后果

- 合并进程时，原跨进程的单写者边界改用不同的数据库角色和连接池来落实，而不是放弃。
- 进程合并后仍保留进程内租约和 fencing，因为可能有多个 `ai` 实例或重启后的残留任务。
- 删除或放宽任何一条，都需要新的决策记录来取代本条。
