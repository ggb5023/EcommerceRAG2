# 商家上线与使用注意事项

[项目入口](../README.md) · [安装](install.md) · [导入知识](knowledge.md) · [客服操作](support.md)

面向商家管理员。安装命令以 [安装](install.md) 为准，导入细节以 [导入知识](knowledge.md) 为准；
本文只列上线前必须确认的条件和容易踩的坑。

## 1. 首次访问必须同时满足四件事

| 条件 | 说明 | 怎么确认 |
| --- | --- | --- |
| 浏览器能真正到达服务器 | 服务器在私网时，需要 VPN 或 SSH 隧道；仅“端口探测成功”不代表 HTTP 请求真的到达 | 在服务器日志里看到对应请求；用真实 HTTPS 客户端访问 `/healthz` 得到 200 |
| 浏览器实际走这条通道 | 浏览器可能绕过 VPN/代理直连，或使用旧的代理配置 | 用独立浏览器配置/代理参数启动，访问地址仍是安装时的正式 origin |
| 服务器证书被信任 | 自签证书或内网 CA 必须导入到受信任根；不要全局关闭证书校验 | 浏览器地址栏无证书告警；证书 SAN 包含你访问的主机名或 IP |
| 一次性安装令牌有效 | `/setup` 只接受安装日志中的一次性 `SETUP_TOKEN`，通常 30 分钟内有效 | 用安装文档的步骤取最后一条令牌；完整复制，不要漏字符 |

补充：

- 服务端当前要求 **TLS 1.3**。请使用较新的 Chrome/Edge/Firefox；如果中间的 VPN、代理或安全设备只支持
  TLS 1.2，应先修中间层，而不是降低服务器 TLS 版本。
- 安装令牌是敏感信息：不要发到聊天、工单、截图或命令回显里；令牌用完或超时即失效。
- 浏览器地址必须使用安装时的正式 origin（例如 `https://<主机>:<端口>`），不要换成 `localhost`、
  `127.0.0.1` 或另一个端口；网关会严格校验 Host。

### 私网访问的通用做法（按你的环境替换）

如果服务器没有公网入口，可用 SSH 隧道把浏览器流量送到服务器：

```text
ssh -N -D 127.0.0.1:1080 <用户>@<服务器>
```

再用一个独立浏览器配置走这个 SOCKS 代理打开正式 origin。不要在日常浏览器里直接改全局代理；
临时配置用完关掉即可。VPN 客户端如果会改写或拦截私网流量，应为其配置分流，或改用 SSH 隧道。

Windows 示例：证书导入当前用户“受信任的根证书颁发机构”（`certutil -user -addstore Root <CA 文件>`）；
Chrome/Edge 用独立的 `--user-data-dir=<临时目录>` 和 `--proxy-server=socks5://127.0.0.1:1080` 启动，
不要复用日常配置。隧道断开后浏览器会报连接失败，先确认隧道仍在运行。

## 2. 首次安装与身份模式

- **身份模式在安装时决定**：默认是内置本地账号，`/setup` 设置 owner 密码；Keycloak 是可选 OIDC
  profile，账号和密码由 Keycloak 管理。两种模式不能在同一个安装目录里混用。
- owner 账号只用于初始化；之后请按需创建员工账号，不要把 owner 密码发给普通客服。
- `access_admin` 属于带外授权，不在页面里创建；需要运维以 migrator 身份操作并记录审计。
- `/setup` 成功后入口永久关闭；忘记密码走安装文档中的本地账号重置流程，不要手工改库。

## 3. 导入与发布知识

- 支持 DOCX、Markdown、CSV（FAQ 模板为 `question,answer`）；单次总量 ≤8 MiB、≤100 个文件。
  首版不支持 PDF、XLSX、OCR 或网页抓取。
- **上传不等于发布**：上传只提交资料。必须依次完成解析/Embedding → 版本预览 → 审核并设置
  `external_allowed` → 发布，客户才能看到。
- 初始分类是 `unclassified`，客户不可见；不要把内部资料审核为对外可见。
- 同一来源内**文件名不变**再上传 = 同一资料的新版本；改文件名 = 新资料。把资料迁到另一个来源时
  要用新的文档标识，否则会返回冲突。
- 内容完全相同的重复导入会复用同一摄取任务，不会重复建任务。
- 来源/文档 ACL 存在时，还要显式允许 `customer` 角色读取；否则客户检索不到。
- 发布后可用审核页的“以客户身份试问”或顾客页面 `/shop/<slug>` 验证引用；试问会产生正常咨询
  记录和模型用量。
- 回退、撤销或收紧 ACL 后，旧答案和 SSE 回放会重新核验；失去依据的客户答案会被隐藏。

## 4. 模型与用量

- 模型 provider 必须使用真实账户配置，配置文件权限保持 `0600`，不要提交到 Git、发给他人或截图。
- **导入阶段使用 Embedding 模型**（例如 1024 维），不使用聊天模型；所以导入时看不到“模型回答”
  是正常的，但会产生 token 用量。
- 客户/员工提问时才使用 control 与 generation 模型；回复质量与检索证据、提示词和服务状态有关。
- 所有调用只记录 token 用量与次数，**不展示货币金额**（决策 0021）；不要把“没有金额”误认为没有计费。
- 模型不可用时，导入或问答会失败并显示状态；先查 provider 配置和用量，不要用 SQL 补写终态。

## 5. 安全与运维

- 只对外发布 Web 端口；数据库和内部 RPC 不暴露到主机网络。私网访问优先用 VPN/隧道或反向代理。
- 安装目录、provider 配置、令牌和证书私钥保持最小权限；不要通过放宽权限来绕过检查。
- 定期按 [备份恢复](backup.md) 演练；升级时先备份，再重建镜像并运行迁移任务。
- 已执行的迁移文件不能修改；服务启动会比对 checksum，改一个字节就起不来。
- 不要用 SQL 手工补写发布、撤销、回退或工单终态；走控制命令和页面操作。
- 临时导入的测试证书、临时浏览器配置和测试账号在评审结束后清理；测试 CA 只从受信任根里删除
  对应的那一张。

## 6. 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 端口探测成功，但浏览器 TLS 握手失败/EOF | VPN 或隧道可能在本地伪造了 TCP 连接；在服务器侧确认请求是否真的到达，改用 SSH 隧道或修分流 |
| 浏览器报 TLS 版本/加密套件错误 | 客户端或中间代理是否只提供 TLS 1.2；换现代浏览器，修中间层，不要降低服务器 TLS |
| 证书告警 | 是否导入了安装时生成的 CA；证书 SAN 是否包含访问的主机/IP；不要关闭全局校验 |
| 地址返回 400 / `invalid host` | 是否用了 `localhost`、`127.0.0.1` 或错误端口；必须使用安装时的正式 origin |
| 安装令牌过期或入口锁定 | 重启 gateway 会生成新令牌；确认复制了完整令牌；`/setup` 成功后入口会永久关闭 |
| 客户看不到刚上传的资料 | 是否完成审核、`external_allowed` 和发布；来源/文档 ACL 是否允许 `customer` |
| 导入后没有模型回答 | 导入只做 Embedding；发布后到顾客/员工页面提问才会调用 control/generation |
| 发布/撤销后旧回答仍在 | 刷新页面；服务端会在终态和回放时重新核验，失去依据的答案应被隐藏 |

## 7. 已知边界

- 单商家、单店铺；多商家 SaaS、计费和跨实例高可用不在首版。
- 首版导入不支持 PDF、XLSX、OCR、网页抓取；DOCX 只提供文档块/表格编号，不提供页码。
- selfhost 首版不提供实时订单/价格/库存查询；售后实时事实按不可用失败关闭。
- 导入不使用聊天模型；发布后的问答会消耗 control/generation token。
- 真实模型评测与人工审查状态以具体版本的评测报告为准，不要把“agent 复核”当成人工质量签字。
