# 产品定位

[项目入口](../README.md) · [架构](architecture.md) · [路线图](../ROADMAP.md)

本文件是判断"做不做"的依据。新功能、新依赖、新集成在动手前先对照本文；不符合的默认不做，确需要做时先写一份[决策记录](decisions/)。

## 为谁做

首版服务**国内电商平台上的中小商家**：在淘宝、抖店、拼多多等平台开店，有 1~10 名客服，或者店主自己兼任客服。

他们的问题：

- **重复咨询多**：发什么快递、几天到、能不能退、尺码怎么选、有没有活动，占了大部分咨询。
- **答错代价高**：承诺错了包邮、退换、活动价，会引起售后纠纷、差评甚至平台处罚。
- **资料分散**：商品参数在后台，政策在文档里，活动规则在群里，新客服要培训很久。
- **高峰扛不住**：大促期间咨询量成倍增加，临时招人来不及。

## 是什么

一个开源、可自部署的**电商客服知识引擎**。商家导入店铺资料，得到一个回答有出处、不乱承诺、答不了就交给人的客服助手。

它是电商平台旁边的**知识与回答层**：不做电商平台，不替代平台客服系统，也不依赖平台开放接口。

和通用知识库工具（Dify、FastGPT、MaxKB 等）相比，区别在于电商场景开箱即用：

- 资料按电商结构处理：商品表（SKU、规格、尺码表）、售后政策、活动规则、FAQ；
- 有时效和版本：活动过期自动失效，政策可以发布、撤回、回滚；
- 答错比不答更糟：每句回答带出处，不臆造价格和赔付，证据不足就追问或转人工；
- 有闭环：答不了的问题汇总成知识缺口，商家补充资料后再发布；
- 可度量：自带电商评测集，输出自动解答率和错答率。

## 怎么接入电商

| 阶段 | 方式 | 说明 |
| --- | --- | --- |
| 首版 | **客服辅助** | 客服把顾客问题粘贴到工作台，拿到带出处的建议回复，一键复制回平台发送。不需要任何平台接口 |
| 后续 | 网页挂件 | 一段 JS 聊天组件，嵌入独立站、H5、小程序网页，顾客直接提问，答不了转人工 |
| 后续 | 开放 API 和适配器 | 问答 API 加订单、库存、物流查询的适配器接口；具体平台由集成方或社区实现 |

资料来源不依赖平台：商品表从平台后台导出 CSV/Excel，政策和 FAQ 是商家自己的文档，历史聊天导出后用来发现高频问题。

## 首版做什么

1. 资料导入：商品表（CSV/Excel，含 SKU、规格、尺码）、政策文档（DOCX/Markdown）、FAQ；导入后预览、审核、发布、撤回、回滚。
2. 活动时效：资料可以设置生效和失效时间，过期内容不再参与回答。
3. 带出处问答：检索已发布资料生成回答，每条结论绑定来源片段。
4. 不确定就收手：缺信息时最多追问一次，仍然不足、资料冲突或超出能力范围就转人工，不编造。
5. 客服工作台：建议回复加一键复制、引用查看、人工接管队列。
6. 知识缺口：汇总转人工和答不了的问题，引导商家补充资料。
7. 一键部署：一条命令启动，附演示店铺数据，显示每千次问答的模型费用。
8. 评测报告：用内置评测集和商家自己的问题，输出自动解答率、错答率、转人工率。

## 首版不做

- 自建电商平台，或对接 Medusa 等电商系统；
- 多商家 SaaS、计费、多实例高可用；
- 通用工作流编排、Agent 平台；
- 网页爬虫、OCR、图片检索、PDF 解析；
- 公开数据集双轨、实时订单、库存和价格查询；
- 某个平台的专用深度对接。

这些不是永久不做，而是首版不做。想提前做，先写决策记录说明理由。

## 价值指标

| 指标 | 含义 | 首版目标 |
| --- | --- | --- |
| 自动解答率 | 无需人工、回答正确的问题占比 | 在真实商家问题上 ≥ 50% |
| 错答率 | 给出错误或无依据承诺的回答占比 | 趋近 0，宁可转人工 |
| 转人工率 | 进入人工队列的问题占比 | 只跟踪，不压低到牺牲错答率 |
| 单次成本 | 每千次问答的模型费用 | 在报告中可见 |
| 上手时间 | 从部署到第一次有效回答 | ≤ 30 分钟 |

## 防跑偏判据

动手前回答三个问题，任何一个答"否"就先停下：

1. 它能让国内商家的客服**更准、更快**地回答顾客吗？
2. 它在 [ROADMAP](../ROADMAP.md) 当前阶段内吗？
3. 它没有让部署和运维变重吗？如果变重了，换来的价值写清楚了吗？
